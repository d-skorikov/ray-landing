# Ray — лендинг «Человек vs ИИ»

Статический сайт для GitHub Pages: сборка не нужна, фреймворков нет.

## Страницы и файлы

| Направление | Страница | Скрипт | Интерактивный тест |
|---|---|---|---|
| Детекция брака (главная) | `index.html` | `defects.js` | Найти 10 бракованных фланцев из 40 за 15 секунд |
| Трекинг объектов | `tracking.html` | `tracking.js` | Уследить за коробкой на конвейере, 3 раунда |
| Поиск движения | `motion.html` | `motion.js` | Заметить 5 событий на ночной камере склада за 25 секунд |
| Подсчёт объектов | `counting.html` | `counting.js` | Сосчитать синие бутылки в потоке за 14 секунд |

Общие файлы: `styles.css`, `common.js` (утилиты, canvas-помощники, форма заявки), `assets/ray_logo_rus.svg`.
На каждой странице есть меню направлений в шапке и блок «Что ещё Ray делает лучше человека».
Первые экраны трекинга, движения и подсчёта — живые canvas-демонстрации «глазами ИИ». Они работают, только пока видны на экране.
Сцены и объекты рисуются кодом: картинок и видео нет, страницы лёгкие.

Шапка, футер и форма повторяются в четырёх HTML-файлах. Меняйте их во всех файлах.
Скрытое поле `direction` в форме подставляет в заявку название направления.

## Главная (детекция брака): структура «Проблема → Осознание → Решение»

1. Первый экран: сплит «уставший оператор / интерфейс машинного зрения».
2. Тест «Человек vs ИИ»: 40 деталей, 10 дефектов, 15 секунд. После теста — «сканирование» ИИ и разбор ошибок.
3. «Почему люди проигрывают?» — три карточки с причинами.
4. Как работает решение: камера → ИИ → решение, плюс преимущества.
5. Калькулятор потерь: 6 вопросов, сценарии 50/70/90%, формула расчёта в развёрнутом виде и дисклеймер.
6. Слайдер «До/После» с тремя примерами: металл, стекло, упаковка.
7. Форма захвата. Расчёт из калькулятора автоматически прикладывается к заявке.
8. Футер.

## Публикация на GitHub Pages

```bash
git init
git add .
git commit -m "Landing"
git branch -M main
git remote add origin https://github.com/<user>/<repo>.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Source: Deploy from a branch → main / (root)**.
Файл `.nojekyll` уже лежит в корне.

## Что заменить перед запуском

| Что | Где |
|---|---|
| Отправка формы. GitHub Pages не принимает POST-запросы, поэтому нужен внешний сервис, например [Formspree](https://formspree.io) или Getform | `common.js` → `FORM_ENDPOINT` (пока пусто — открывается почтовый клиент) |
| E-mail для заявок | `common.js` → `CONTACT_EMAIL`, футер во всех четырёх страницах |
| Телефон, адрес, соцсети | футер во всех четырёх страницах |
| Логотип Ray — `assets/ray_logo_rus.svg` (шапка и футер); favicon пока условный | `<link rel="icon">` во всех страницах |
| Логотипы клиентов (сейчас заглушки «ЛОГОТИП») | `.partners` во всех страницах |
| Ссылка на политику обработки персональных данных (152-ФЗ) | чекбокс согласия в форме на всех страницах |
| Примеры «До/После» нарисованы в SVG. Лучше заменить их реальными фото | `index.html` → `.ba__case`: в `.ba__img` поставьте `<img>`, в `.ba__ai` — рамки поверх |
| Цифры в маркетинговых текстах («до 30%», «−40% через 30 минут», «48 часов», «0,03 с», «0,04 с») | Проверьте, что можете их подтвердить |

## Калькулятор

```
Месячный выпуск      = выпуск в день × рабочие дни
Брак в месяц         = месячный выпуск × % брака
Брак у клиента       = брак × доля брака у клиента
Потери от возвратов  = брак у клиента × (цена + стоимость возврата)
Внутренние потери    = (брак − брак у клиента) × цена
Экономия в год       = (возвраты + внутренние) × 12 × доля предотвращаемого брака
```

Значения по умолчанию взяты из примера: 2000 шт. в день, 22 дня, 2% брака, 30% брака у клиента, 800 ₽ за единицу, 1200 ₽ за возврат.
Результат: 1 020 800 ₽ в месяц и 8,57 млн ₽ в год при сценарии 70%.
На разбор одной рекламации закладывается 1,5 часа (`defects.js`, `client * 1.5`).
